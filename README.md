# فايكو | Fayko

منصة تواصل اجتماعي عربية قيد التطوير باستخدام Flutter/Dart وخادم Node.js مع PostgreSQL.

## الموجود حالياً

- تطبيق Flutter بواجهة عربية RTL، وشاشة تسجيل الدخول وإنشاء الحساب.
- تكامل برمجي مبدئي مع API للمصادقة واستعادة الجلسة وحفظ رمز الدخول في تخزين آمن.
- خلاصة المنشورات النصية مرتبطة بالكود الخاص بالخادم: تحميل المنشورات، نشر منشور، الإعجاب وإلغاء الإعجاب، قراءة التعليقات وإضافتها.
- ملف شخصي يعرض معلومات الحساب مع تعديل الاسم والنبذة وتسجيل الخروج.
- تصنيفات اهتمامات عربية/عالمية يمكن حفظها بالحساب (رياضة، ألعاب، ديني، تعليم، تصاميم، تقنية، أخبار، وغيرها)؛ الخلاصة تدعم تصفية بسيطة حسب الاهتمامات، بينما التوصيات الذكية وتغذية الترندات العالمية تحتاج مصادر وبيانات استخدام فعلية وما زالت لاحقة.
- واجهة الريلز مرتبطة الآن بمسارات رفع MP4 وتشغيل الفيديو من روابط خاصة مؤقتة؛ الميزة تبقى معطّلة إلى أن يُضبط مخزن R2 على الخادم، ولم يُجرَ رفع فيديو حقيقي إلى مخزن خارجي بعد.
- عند إنشاء المنشور يمكن اختيار تصنيفه، وتُضاف منشورات تمهيدية رسمية لتوضيح الأقسام للمستخدمين الجدد.
- شاشة بحث عن المستخدمين من API، مع متابعة وإلغاء المتابعة وفتح محادثة مباشرة.
- دردشة نصية مباشرة مرتبطة بالخادم: إنشاء المحادثات، حفظ الرسائل، سجلّ الرسائل، عدد غير المقروء والتحديثات اللحظية عبر Socket.IO عند اتصال الخادم.
- خادم API أولي وقاعدة PostgreSQL لمستخدمين ومنشورات وإعجابات وتعليقات ومتابعة.
- واجهات API للبحث عن المستخدمين وعرض ملفاتهم والمتابعة وإلغاء المتابعة.
- اختبارات Flutter وNode مكتوبة، وتضم اختبارات تكامل تستخدم PostgreSQL وSocket.IO ومسارات الريلز في CI. نجاح CI لكل التغييرات الأخيرة قيد التحقق.
- مسارات CI تفحص الكود والاختبارات فقط؛ لا تبني APK.

## الحالة الحالية — مهم

هذا **ليس تطبيقاً مكتملاً بعد**. نجحت اختبارات Flutter والخادم في إصدارات سابقة، لكن إضافة رفع وتشغيل الريلز جارية وتحتاج تأكيد اختبارات CI الجديدة وتجربة Android فعلية. لم يتم نشر الخادم المشترك، ولم يُضبط مخزن الفيديو الخارجي حتى الآن.

لم يُنشأ APK في هذه المرحلة، عمداً. تمت إضافة قالب Render لخادم HTTPS وقاعدة PostgreSQL، لكن نشره لم يُنفّذ بعد ويحتاج إلى حساب Render وربط المستودع. رفع الريلز صُمّم حول مخزن R2 خاص وروابط توقيع مؤقتة، لكن يلزم إنشاء المخزن وضبط مفاتيحه في إعدادات Render ثم تجربة رفع فيديو فعلي قبل اعتباره جاهزاً. يتبقى أيضاً ترندات عالمية بمصادر موثوقة، رفع الصور، إشعارات الهاتف والمكالمات، التشفير الطرفي، أدوات إدارة البلاغات، تجديد الجلسات واستعادة الحساب، ومراجعة أمان شاملة وتجربة فعلية على جهازين Android.

## تشغيل بيئة التطوير

1. ثبّت Docker مع Compose وFlutter stable.
2. من مجلد `backend` انسخ `.env.example` إلى `.env` وبدّل `JWT_SECRET` بقيمة عشوائية قوية.
3. شغّل `docker compose up --build` من مجلد `backend`.
4. شغّل Flutter مع عنوان API المحلي المناسب للمحاكي:
   `flutter run --dart-define=FAYKO_API_BASE_URL=http://10.0.2.2:4000/api/v1`

عنوان `10.0.2.2` مخصص لمحاكي Android للوصول إلى الجهاز المضيف؛ ليس عنوان إنتاج ولا عنواناً مضموناً لهاتف فعلي. قبل استعمال هاتف أو نشر عام، يجب تجهيز عنوان خادم HTTPS قابل للوصول وتحديده عبر `FAYKO_API_BASE_URL`.

## التقنية الحالية

- Flutter / Dart للعميل.
- Node.js 22 وExpress 5 للخادم.
- PostgreSQL للبيانات.
- تخزين الفيديو: مسارات رفع/تنزيل بروابط مؤقتة موقعة عبر S3-compatible storage مثل Cloudflare R2؛ غير مفعّل حتى تُضبط أسرار البيئة وتنجح تجربة الرفع الحقيقية.

## أمان المستودع

لا تضع كلمات مرور أو مفاتيح API أو مفاتيح توقيع داخل المستودع. ملف `backend/.env.example` قالب فقط؛ لا ترفع ملف `.env` الحقيقي.
