# دراسة المنافسين والخطة الاستراتيجية لفايكو
**الإصدار:** 1.0  
**تاريخ المراجعة:** 25 أكتوبر 2026  
**الحالة:** دراسة تأسيسية — تحتاج تحديثاً دورياً قبل قرارات الإطلاق

## 1. لماذا نكتب هذه الدراسة؟
هدف فايكو ليس نسخ عشرة تطبيقات وجمع كل خصائصها في شاشة مزدحمة. الهدف هو معرفة القيمة التي يقدمها كل منتج، وفهم المبادئ الهندسية المعلنة، وتحديد المقايضات والمخاطر، ثم اختيار ما يناسب منتجاً عربياً ناشئاً بموارد محدودة.

### منهجية وحدود الدراسة
- نعتمد أولاً على صفحات الشركات الرسمية، ووثائق المنتج والهندسة المنشورة علناً.
- نميّز بين **حقيقة منشورة** و**استنتاج تصميمي** و**فرضية تحتاج اختباراً**.
- كلمة «خطأ» لا تُستخدم إلا عند وجود دليل واضح؛ كثير من القرارات هي مقايضات بين الخصوصية والراحة، أو الاكتشاف والتحكم، أو النمو والكلفة.
- لا تكشف المصادر العامة كامل الأنظمة الداخلية أو كل نتائجها. لذلك لا نزعم أننا نعرف الشيفرة السرية أو جميع إخفاقات المنافسين.
- تمثل هذه الدراسة نقطة انطلاق، لا تدقيقاً أمنياً أو قانونياً، ولا ضماناً للنجاح التجاري.

## 3. الاستنتاج الاستراتيجي لفايكو
يمكننا الجمع بين هذه القدرات على مستوى تجربة المستخدم، لكن ليس من الحكمة دمج كل الأنظمة في كتلة برمجية واحدة. **توحيد الواجهة لا يعني خلط الصلاحيات والبيانات والبنية التقنية.**

### مبادئ المنتج
1. **عربي أولاً:** RTL صحيح في كل الشاشات، نصوص عربية واضحة، بحث جيد باللغة العربية، وتجربة مناسبة لاتصالات وهواتف متفاوتة الإمكانات.
2. **واجهة واحدة، أقسام مفهومة:** الرئيسية، الفيديو، الرسائل، المجتمعات/القنوات، الملف الشخصي. لا نضع كل شيء في شاشة واحدة.
3. **خصوصية قابلة للفهم:** إعدادات واضحة، خيارات خصوصية افتراضية حذرة، توضيح صريح لنوع التشفير، وسهولة حظر الحسابات والإبلاغ عنها.
4. **تحكم بالخلاصة:** شرح مبسط لسبب ظهور المحتوى، وخيارات «غير مهتم»، إخفاء حساب، إعادة ضبط الاهتمامات، والتحكم بالتوصيات.
5. **سلامة منذ البداية:** مكافحة السبام، الإبلاغ، الحظر، إجراءات إشراف قابلة للتدقيق، وتدابير عمر مناسبة.
6. **الأداء قبل الزينة:** صفحات سريعة، ترقيم صفحات، صور مصغرة، تحميل متدرج، ضغط/تحويل وسائط، ومراقبة الكلفة.
7. **ميزة تستحق العودة:** مجلدات حفظ ذكية وتنظيم المنشورات والفيديوهات موضوعياً؛ نختبر إن كانت فعلاً مفيدة بدلاً من افتراض ذلك.

## 4. القرارات الهندسية الأولية
هذه توصيات مشروعنا وليست نسخاً حرفياً لبنية المنافسين.

- **التطبيق:** الاستمرار باستخدام Flutter/Dart للواجهة، مع فصل كل ميزة إلى وحدات مفهومة.
- **الخادم:** اختيار NestJS أو Go بعد تجربة صغيرة ومقارنة قدرة الفريق ومتطلبات النشر. لا نختار لغة بناءً على شعبية فقط.
- **قاعدة البيانات:** PostgreSQL كبداية للبيانات الأساسية والعلاقات. لا نضيف MongoDB أو Cassandra للرسائل قبل ظهور حاجة مثبتة بقياسات.
- **الوسائط:** تخزين كائنات خاص افتراضياً مع صلاحيات رفع/تنزيل مؤقتة، صور مصغرة، حدود حجم، وفحص نوع الملف؛ ثم تحويل الفيديو وبثه تدريجياً.
- **الخلاصة:** البداية بخلاصة من الحسابات المتابَعة مع ترتيب زمني/قواعد بسيطة؛ ثم إضافة ترتيب شخصي على مراحل وباختبارات مقارنة.
- **المحادثات:** تحديد قرار التشفير والنسخ الاحتياطي وتعدد الأجهزة قبل الإنتاج. لا نكتب بروتوكول تشفير خاصاً بنا؛ أي تشفير طرف إلى طرف يحتاج مكتبة/بروتوكولاً موثوقاً ومراجعة متخصصة واختبارات.
- **التشغيل:** اختبارات، سجلات لا تكشف المحتوى الخاص، مراقبة الأعطال والكلفة، نسخ احتياطية واستعادة مجرّبة، وحدود معدل للواجهات الحساسة.
- **الأمان:** لا توضع كلمات المرور أو مفاتيح API أو مفاتيح التوقيع في GitHub. تُدار الأسرار خارج المستودع.

## 5. ما الذي لا نبنيه في النسخة الأولى؟
لتجنب التضخم، لا نبدأ بتطبيق كامل يشبه كل منافس بكل خصائصه. نؤجل:
- خوارزمية توصية بالذكاء الاصطناعي واسعة النطاق.
- بثاً حياً ومكالمات فيديو جماعية متقدمة.
- بنية خدمات مصغرة متعددة قبل وجود حمل يبررها.
- مخزن رسائل ثانياً قبل أن تثبت القياسات ضرورته.
- إعلانات أو نظام مدفوعات قبل تأسيس الثقة وقياس الاستخدام.
- ميزات تشفير متقدمة قبل قرار واضح واختبارات ومراجعة أمنية.

## 6. خارطة طريق على مراحل
### المرحلة A — تثبيت الأساس
- [ ] تعريف الجمهور الأول ومشكلة واحدة يحلها فايكو بشكل أفضل.
- [ ] توثيق متطلبات الخصوصية والسلامة والإبلاغ والحظر وحذف الحساب.
- [ ] رسم تدفقات التسجيل والملف والمنشور والمتابعة والدردشة.
- [ ] تحديد مؤشرات النجاح ومعايير الأداء المستهدفة قبل القياس.

### المرحلة B — نسخة MVP قابلة للاختبار
- [ ] تسجيل ودخول واستعادة حساب بصورة آمنة.
- [ ] ملف شخصي ومتابعة/إلغاء متابعة.
- [ ] منشورات نصية وصور وإعجاب وتعليق.
- [ ] خلاصة بسيطة مع ترقيم صفحات.
- [ ] إعدادات خصوصية وحظر وإبلاغ وأدوات إشراف للمشرفين.
- [ ] اختبارات الوحدة والواجهات، واختبارات API وأمان أساسية.

### المرحلة C — رسائل ووسائط موثوقة
- [ ] إرسال/استقبال الرسائل مع حالات الإرسال والتسليم والفشل وإعادة المحاولة.
- [ ] مرفقات بصلاحيات وصول محدودة وحدود للحجم والنوع.
- [ ] سياسة واضحة للاحتفاظ والنسخ الاحتياطي والحذف.
- [ ] اختبار الأداء على اتصالات ضعيفة وأجهزة متوسطة.

### المرحلة D — أسباب العودة
- [ ] قصص مؤقتة مع توضيح معنى الحذف وحدوده.
- [ ] ريلز وفيديو بعد إضافة pipeline تحويل وتخزين وتسليم قابل للمراقبة.
- [ ] مجلدات حفظ ذكية.
- [ ] قنوات/مجتمعات عامة بعد توفير إدارة ومكافحة سبام مناسبة.

### المرحلة E — التوصيات والتوسع
- [ ] قياس جودة الخلاصة ومصادر عدم الرضا.
- [ ] اختبار تغييرات صغيرة بمقارنة عادلة، لا نشر تغييرات ضخمة دفعة واحدة.
- [ ] إضافة تنوع وتفضيلات سلبية وضوابط عمرية وشرح مناسب للتوصيات.
- [ ] مراجعة بنية التخزين والخدمات استناداً إلى حمل حقيقي لا توقعات مبالغ بها.

## 7. مؤشرات نجاح لا يجوز تجاهلها
تُراجع هذه المؤشرات مع الحفاظ على خصوصية المستخدم وعدم جمع بيانات غير ضرورية:

| المجال | المؤشر | لماذا نراقبه؟ |
|---|---|---|
| الاعتمادية | نسبة الجلسات الخالية من الانهيار | هل التطبيق مستقر؟ |
| الأداء | زمن استجابة API عند المئين 95 (p95) | هل التجربة سريعة حتى عندما يزداد الضغط؟ |
| الرسائل | نسبة التسليم الناجح وزمن التسليم | هل التواصل موثوق؟ |
| الوسائط | نسبة نجاح الرفع والتشغيل | هل يعمل الفيديو على شبكات وأجهزة مختلفة؟ |
| التبني | الاحتفاظ في اليوم 1 واليوم 7 واليوم 30 | هل يعود الناس لأن المنتج مفيد؟ |
| السلامة | زمن مراجعة البلاغات ونسبة تكرار المخالفات | هل نستجيب للمشاكل؟ |
| الخصوصية | نجاح عمليات حذف الحساب والبيانات ووضوحها | هل يملك المستخدم تحكماً حقيقياً؟ |
| الكلفة | تكلفة الخدمة لكل مستخدم نشط | هل يمكن الاستمرار دون هدر؟ |
| الجودة | نسبة «غير مهتم» والإخفاء/الإبلاغ من مرات الظهور | هل الخلاصة مفيدة أم مزعجة؟ |

لا نحدد أرقاماً مستهدفة عشوائية الآن. نضع حدوداً أولية بعد بناء النموذج وقياس خط أساس، ثم نرفع المعايير تدريجياً.

## 8. كيف نختار أول جمهور؟
لا نستهدف العالم كله من أول إطلاق. نختار مجموعة صغيرة يمكن الوصول إليها وفهم احتياجاتها، مثل صناع محتوى عرب أو مجتمعات اهتمام محددة. ثم:
1. نجري مقابلات قصيرة واختبارات استخدام بموافقة المشاركين.
2. نختبر هل ميزة مجلدات الحفظ، والواجهة العربية، وتجميع المنشورات والدردشة ضمن تجربة واحدة تحل مشكلة فعلية.
3. نقيس العودة والاستخدام المتكرر، وليس عدد الحسابات المسجلة فقط.
4. نصلح أسباب المغادرة قبل توسيع التسويق.

## 9. سجل المخاطر والقرارات

## 10. قرارنا الآن
**الأولوية ليست إضافة عشرات الميزات. الأولوية هي اختيار وعد واحد يستطيع فايكو الوفاء به.**

الاقتراح المبدئي: **منصة عربية سهلة وخفيفة تجمع المنشورات والدردشة وتنظيم المحتوى المحفوظ، مع إعدادات خصوصية واضحة وأدوات سلامة موثوقة.** الفيديو والمجتمعات والتوصيات تتوسع على مراحل بعد أن يثبت المنتج الأساسي فائدته.

هذه فرضية استراتيجية قابلة للتغيير بناءً على مقابلات المستخدمين والاختبارات، وليست حقيقة مثبتة بعد.

- سجّل القرار الناتج وسببه، والفرضية المراد اختبارها، والمؤشر الذي سيحدد النجاح.
